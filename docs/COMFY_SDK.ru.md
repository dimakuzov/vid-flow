# Транспорт Comfy SDK

По умолчанию доска ходит в ComfyUI и Comfy Cloud через официальный `@comfyorg/sdk` (Comfy API v2). Прямые HTTP-вызовы (`legacy`) остаются вторым транспортом. Формат `data/comfy_queue/<id>.json` и правила для агентов не меняются: выбор делает `src/lib/comfy/transport.ts`, реализация SDK — `src/lib/comfy/sdk.ts`. Прямые модули `client.ts` и `cloud.ts` остаются, их включают `COMFY_TRANSPORT=legacy` или кнопка «Напрямую» в шапке.

Нужен Node 22+. Пакет в бете (проверено на 0.5.0).

## Запуск локально (ComfyUI + comfy-api-proxy)

SDK не говорит с ComfyUI на `:8188` напрямую, только через прокси.

```bash
pip install comfy-api-proxy
comfy-api-proxy   # перед ComfyUI; порт по умолчанию 8189, настройки — в документации пакета
```

```bash
npm run dev
```

`COMFY_BASE_URL` по умолчанию `http://127.0.0.1:8189`. `COMFY_URL` в этом режиме нужен только для чтения текстовых выходов (см. ниже). Ключ для прокси не нужен: доска создаёт локальный клиент без ключа и не передаёт ему `COMFY_API_KEY` из окружения.

## Comfy Cloud

Ключ тот же: `COMFY_CLOUD_API_KEY` в `.env.local`. Клиент облака создаётся с `apiKey`, переменная `COMFY_BASE_URL` на время его создания снимается (для SDK пустой адрес — это Comfy Cloud). `COMFY_CLOUD_URL`, если задан, ведёт на другой стенд.

Правило из AGENTS.md сохраняется: платный прогон уходит только с доски, после галочки «Разрешить платную отправку в Comfy Cloud». Повторных отправок нет.

## Переключатель в доске

В шапке, справа от EN/RU: «Direct» (прямые вызовы) и «SDK». Выбор пишется в `data/comfy_transport.txt` и важнее `COMFY_TRANSPORT`; пока файла нет, работает переменная. Пока есть задание в статусе `running`, кнопки заблокированы, а `POST /api/comfy/transport` отвечает 409: задание, ушедшее одним транспортом, другой по id не найдёт. Задания в статусе `pending` переключению не мешают.

## Проверено на настоящем ComfyUI

25.10.2026 доска работала в режиме SDK через `comfy-api-proxy` 0.1.6 перед ComfyUI 0.41.0 (Windows, `@comfyorg/sdk` 0.5.0). Эти этапы прошли от начала до конца и дали ожидаемые файлы: локация Krea 2, первый кадр Qwen Image 2.1 (несколько загруженных картинок), превью LTX 2.5 (видео со звуком) и превью MiniMax H3. Отмена работающего финала MiniMax H3 очистила очередь ComfyUI и вернула этап в состояние «свободен». Не проверялись: ошибки отклонённого графа, путь текстового выхода Whisper и платный облачный путь.

## Что SDK не умеет, и как это видно на доске

- **Очередь.** В SDK нет чтения общей очереди (список ждущих и выполняемых заданий), поэтому `readComfyQueue()` в SDK-режиме бросает ошибку, `queuePosition` у заданий остаётся `null`, а «потерянное» задание по таймауту не определяется. Если сервис забудет задание, это, вероятно, станет ошибкой чтения (`NotFound`); живьём не проверено.
- **Отмена.** `job.cancel()` документирован только в типах; сигнатуры ожидания в документации нет. Ошибки отмены глушатся, как и раньше.
- **Текстовые выходы.** SDK их не отдаёт: у задания с `PreviewAny` (Whisper в «Build project») `outputs` пуст. Доска берёт текст из истории ComfyUI на `COMFY_URL` (id задания в SDK равен prompt_id ComfyUI), поэтому в SDK-режиме для таких заданий ComfyUI на :8188 должен быть доступен напрямую. Файлы идут через SDK. Для облака этого обхода нет.
- **Тип выходов.** Берутся `image` и `video`. `audio`, `file`, `latent` доска не забирает. Как SDK классифицирует выход Continuity (`mmc_video`), не проверено.
- **Ошибки нод.** Разбор `node_errors` из `details` у `InvalidWorkflow` написан по формату ComfyUI; формат `details` в SDK не описан и живым прогоном не проверен.
- **Имена файлов.** Загрузка идёт через `assets.fromBytes` (по хэшу), имя файла в графе заменяется на дескриптор при отправке. Поэтому подмена имён (`renameUploads`) в этом режиме — no-op: имя остаётся прежним.
- **Адрес облака.** `COMFY_CLOUD_URL` работает через `COMFY_BASE_URL` внутри SDK.
