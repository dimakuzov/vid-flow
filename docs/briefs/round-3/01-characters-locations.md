# Бриф 01. Персонажи и локации

Сначала `docs/briefs/round-3/00-overview.md` — правила, запреты, зоны файлов, порт 3481, `DATA_ROOT=$TEMP/frameboard-r3-chars`. Ветка `r3-characters-locations`, worktree `../vid-flow-r3-chars`.

## Как сейчас и что не так

**Персонажи** (`characters`) — единственный этап без воркфлоу доски. «Отправить агенту» запускает CLI-агента в режиме `agent` (`src/lib/agent/providers.ts`, `claudeInvocation`): он сам читает `playbooks/workflows/characters_comfy.en.md`, ищет базу в `data/characters/{name}/`, собирает граф `character_outfit_qwen21.json` (image 1 — персонаж, image 2 — образец одежды из `refs/`), ставит задание в ComfyUI, ждёт, смотрит результат и **сам кладёт его в `approve/{name}_{shotId}.png`**. Так требуют `AGENTS.md` («Characters stage») и текст задачи в `src/lib/series/agent-request.ts` (`renderLlmTask`, ветка `stageId === "characters"`).

Что из этого получается у пользователя (эпизод episode_4, кадр s18):
- прогон длится больше минуты, хотя на других этапах агент отвечает за 5–10 секунд (там агент только пишет `prompt.md`, а ComfyUI запускает доска);
- агент **сам утверждает** результат — пользователь этого не хочет: утверждает только он;
- база персонажа бывает листом из трёх панелей (`young_woman.png`), агент каждый раз вырезает нужную;
- у персонажа без папки в библиотеке (`man`) агент застревает и оставляет этап незакрытым.

Черновик манифеста уже есть: `playbooks/workflows/drafts/character_outfit.bind.json` (+ `drafts/README.md`). Утверждение персонажей и разбор имён файлов — `approveFiles` в `src/lib/series/mutations.ts` (уже умеет `Lena_mom_body.png` → мама; не ломать). Входы этапа на странице — `characterInputs` в `src/lib/series/stage-inputs.ts`.

**Локация** (`location`) уже на схеме доски: `location_views` (4 ветки по разделам `prompt.md`) и `location_krea2`. Выбор вида из библиотеки — `src/lib/series/library.ts`, `location-library.tsx`.

## Что нужно

### 1. Персонажи на схему доски (главное)

1. Манифест персонажей в `playbooks/workflows/comfy/` (из черновика): граф `character_outfit_qwen21.json`, **один прогон на персонажа**: image 1 — база персонажа, image 2 — образец одежды (необязателен; нет — узел образца удаляется, одежда — текстом промпта).
2. Агент на этом этапе работает в режиме `text`, как на остальных: пишет только `prompt.md`. Промпт должен уметь задать одежду **каждому персонажу кадра отдельно** — разделы `## <имя персонажа>` (механизм `sections` уже есть в `binding.ts`; имена разделов — строчная латиница, имена персонажей у нас такие). Пустой раздел — персонаж не перегенерируется.
3. Доска сама запускает по прогону на персонажа (правка в `src/lib/comfy/stage-run.ts` / `queue.ts`: несколько заданий на один запуск этапа). Имя результата в `output/` начинается с имени персонажа (`{name}_{shotId}_v1…`), чтобы `approveFiles` и пользователь сразу видели, чей вариант.
4. **Никакого автоматического аппрува.** Результат — только в `output/`. Этап «утверждён», когда пользователь утвердил по файлу на каждого персонажа (как сейчас считает `deriveStageStatus`).
5. Новый источник входа для базы персонажа (например `library:character`): картинка из `data/characters/{name}/` — `full_body.png`, иначе старые имена (`body.png`), иначе первая картинка без `copy`. Логика выбора базы уже есть в `characterBaseFiles` (`stage-inputs.ts`) — вынести и переиспользовать, не дублировать. `refs/{name}_base.*` этапа важнее библиотеки (пользователь подложил свою базу на кадр).
6. Нет базы у персонажа — прогон по нему не ставится, остальные идут; на странице этапа и в ошибке видно: «нет базы для man: положите картинку в data/characters/man/».
7. `AGENTS.md` (раздел «Characters stage»), `playbooks/workflows/characters_comfy*.md`, `playbooks/stages/characters*.md`, текст задачи в `renderLlmTask` — привести к новой схеме: агент пишет промпт, ComfyUI запускает доска, утверждает пользователь. Ветку `agent`-режима для персонажей убрать, если у этапа есть доступный воркфлоу (это уже так работает в `stageBoardQueues` — проверить).
8. Плейбук модели для промпта одежды: `playbooks/models/qwen_outfit.en.md` + русский. Правила: менять только одежду из просьбы пользователя; лицо, волосы, фигура, поза, фон, остальная одежда — как на image 1; образец одежды — image 2, если есть; не описывать внешность по памяти.

### 2. Базы персонажей

- Если база — лист из нескольких панелей, доска не должна резать её каждый раз. Достаточно: на странице этапа видно, какая картинка уйдёт базой, и подсказка «положите full_body.png во весь рост». Автоматическую нарезку **не делать**.

### 3. Локации

- Пройти по плейбукам локации (`qwen_location*`, `krea2_location*`, `playbooks/stages/location*`) и привести их к тем же правилам, что первый кадр в раунде 2→3: что пользователь чаще всего правил — смотреть **только** `prompt_history.json` и `agent_request.json` этапов `location` в `data/episodes/*/shots/*/location/` (только чтение, только эти два файла). Итоги — в плейбук и в отчёт.
- Новые воркфлоу локаций добавлять, **только когда пользователь пришлёт граф** (спросить в чате, есть ли он). Без графа — не придумывать.
