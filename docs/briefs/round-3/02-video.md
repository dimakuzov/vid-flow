# Бриф 02. Видео (превью) и финальный рендер

Сначала `docs/briefs/round-3/00-overview.md` — правила, запреты, зоны файлов, порт 3482, `DATA_ROOT=$TEMP/frameboard-r3-video`. Ветка `r3-video`, worktree `../vid-flow-r3-video`.

## Как сейчас

- **Видео (превью)** (`video_preview`): `video_i2v` (Wan 2.2, по умолчанию), `video_flf` (Wan, первый и последний кадр), `video_ltx` (LTX 2.5, 24 к/с, со звуком и речью). Плейбуки — `playbooks/models/wan_video*.md`, `ltx_video*.md`. Длительность — меню этапа (`settings:seconds`).
- **Финальный рендер** (`final_render`): `final_wan_720` (по умолчанию без реплик, 24 к/с), `final_h3`, `final_h3_768`, `final_h3_768_face` (MiniMax H3, речь), `final_heygen` (Comfy Cloud, платно), `final_i2v`, `final_flf`. Выбор по умолчанию — `defaultWhen` (`speech` / `dialogue` / `silent`) в манифестах, логика — `src/lib/comfy/workflows.ts`.
- Агент видит в задаче реплики (`speech.md`), действие кадра под картинки (`action.md`), описание утверждённого первого кадра и все замечания пользователя (`src/lib/agent/shot-context.ts`). Не ломать.
- Агент может предложить другой воркфлоу: `suggestedWorkflow` в `agent_request.json`; доска показывает предложение, сама не переключает.

## Что не так

1. **Финал берёт текущий `prompt.md` эскиза**, а не тот, с которым сделан утверждённый ролик (входы с `"stage": "video_preview"` в манифестах `final_*`). Пользователь утвердил эскиз, потом поправил промпт и не перегенерировал — в финал уходит другой текст. Промпт LTX (`use image as the first frame. …`) к тому же не подходит Wan-финалу.
2. Выбор воркфлоу по задаче слабый: только `defaultWhen` по репликам. Нет подсказки «нужна конечная поза → FLF», «есть речь → LTX или H3», а LTX в финале нет вообще.
3. Новые видео-воркфлоу пользователь будет присылать — каждый должен подключаться без правки кода и с плейбуком.

## Что нужно

1. **Промпт финала из утверждённого эскиза.** ComfyUI пишет граф в метаданные ролика (проверить, где лежит текст для mp4: `SaveVideo` / `CreateVideo`; для PNG так уже читается в `src/components/stage/png-metadata.ts`). Новый источник текста в манифесте (например `from: "approve-meta"`, `of: <вход video>`, `node: <id ноды промпта>`): текст промпта из самого нового файла `video_preview/approve/`. Нет метаданных — запасной `prompt.md` эскиза, с пометкой в задаче агенту и в `run_log.md`. Учесть, что эскиз мог быть сделан разными графами (Wan / LTX): нода промпта у них разная — манифест должен это выражать, а не код.
2. **Финал под эскиз LTX**: если утверждённый эскиз сделан LTX, финал по умолчанию — LTX в финальном разрешении (новый манифест `final_ltx*` на том же графе, разрешение и fps — константами в манифесте, как `final_wan_720`). Если эскиз Wan — как сейчас. Где взять, каким графом сделан эскиз, — метаданные ролика или имя файла (`{shotId}_ltx`, `{shotId}_i2v`); выбрать надёжное и описать в контракте.
3. **Выбор воркфлоу по задаче.** Расширить правила по умолчанию (`defaultWhen` или новое поле манифеста, решить и описать в `graph-binding.md`): реплики в кадре → вариант с речью; диалог → H3; нет реплик → Wan. Агент этапа получает в задаче короткую таблицу «когда какой вариант» из плейбука этапа и пишет `suggestedWorkflow`, если выбранный не подходит. Доска сама не переключает — только показывает предложение (как сейчас).
4. **Плейбуки**: `playbooks/stages/video_preview*.md`, `final_render*.md` — таблица выбора варианта; `ltx_video*.md` — дописать, если по ходу работы что-то выяснится (без настоящих прогонов — только то, что следует из графа и контракта).
5. **Новые воркфлоу** — только когда пользователь пришлёт граф (спросить в чате). Для каждого: граф, манифест, плейбук модели (ru + en), строка в таблицах (`playbooks/workflows/comfy/README.md`, `docs/contracts/graph-binding.md`, плейбук этапа), тест сборки, как `src/lib/comfy/ltx.test.ts`. Проверка нод — только `GET /object_info/<класс>`.
6. Comfy Cloud (`final_heygen`, `target: "cloud"`) — правила не менять: облако только по галочке пользователя на один запуск.
