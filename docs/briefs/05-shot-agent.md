## Как сейчас и что не так

Агент на доске — разовый запуск на один этап (`agent_request.json` этапа: провайдер `manual | ollama | claude`, модель, режим). Понятия «агент кадра» нет:
- каждая кнопка запуска (`src/components/board/bulk-menu.tsx`: «Агенты по кадрам» над «Кадр», «▶ Агент» на кадре, «▶ Все кадры» над этапом; страница этапа — `agent-panel.tsx`) заново спрашивает агента и модель; выбор помнится только в `localStorage` браузера, один на все кадры;
- в заголовке кадра (`ShotHeader` в `series-board.tsx`) не видно, кто работает с кадром;
- «▶ Агент» на кадре выглядит как «создать ещё одного агента», хотя на деле это ещё один разовый запрос.

Код массовых запусков: `src/lib/series/bulk.ts` (`runStageForAllShots`, `runNextStageForAllShots`, `runNextStageForShot`), маршруты `src/app/api/episodes/[episodeId]/{next-stage,stages/[stage]/run-all}`, `.../shots/[shotId]/next-stage`. Запрос агенту — `submitAgentRequest` в `src/lib/series/agent-request.ts`. Список агентов доски — `listAgentRuns` в `agent-dispatch.ts`, `GET /api/agent/runs`.

## Что нужно пользователю

1. **У кадра есть свой агент**: провайдер и модель (например «Claude Code · Sonnet 5.5»). Хранится в папке кадра: `shots/{shotId}/agent.json` → `{ provider, model, updatedAt }`. Пишет только доска.
2. **Назначение агента кадру**:
   - «▶ Агент» на кадре — меню «Агент кадра: [провайдер, модель] — Сохранить / Запустить следующий этап / Остановить». Выбор сохраняется в `agent.json` кадра.
   - «Агенты по кадрам» над «Кадр» — выбранный агент назначается **всем кадрам без своего агента**, у кадров с агентом остаётся их агент; затем каждому кадру — его следующий этап его агентом. Кадры, где агент уже работает или этап пройден, не трогаются (как сейчас).
3. **«▶ Все кадры» над этапом** запускает этап на каждом кадре **агентом этого кадра**. Меню спрашивает агента только если есть кадры без агента: «Для N кадров без агента: [провайдер, модель]» — и **назначает этот выбор этим кадрам** (пишет их `agent.json`), потом запускает. Если у всех кадров агент есть — без выбора, только «Запустить на N кадрах».
4. **Заголовок кадра показывает его агента и состояние**: «Claude Code · Sonnet 5.5 — работает: Персонажи, с 14:05» / «ждёт очереди» / «свободен» / «нет агента». Данные — из `agent.json` и активных запросов кадра; в `ShotSummary` добавить `agent: { provider, model } | null` и `agentActivity: { stageId, status, since } | null`.
5. **Страница этапа**: «Отправить агенту» по умолчанию берёт агента кадра; поменять можно для одного запуска (галка «запомнить для кадра» — записать в `agent.json`).
6. Модель агента кадра передаётся в запрос как сейчас (`provider`, `model` в `submitAgentRequest`); `agent_request.json` хранит, кем фактически выполнен запуск.

## Проверка

- Тесты: `agent.json` пишется и читается; «Все кадры» с кадрами без агента назначает выбранного и запускает каждый кадр его агентом (подменённый провайдер, проверить `request.provider/model` по кадрам); «Агенты по кадрам» не меняет уже назначенных; `ShotSummary.agent/agentActivity`.
- В браузере на временной `DATA_ROOT` (отдельный порт, `COMFY_URL=http://127.0.0.1:9`, агент «в чате» или подменённый): назначить агента кадру, увидеть его в заголовке, «Все кадры» без повторного выбора.
