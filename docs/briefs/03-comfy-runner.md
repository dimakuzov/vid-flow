# Бриф 3. Запуск в ComfyUI

Сначала прочитай `docs/briefs/00-overview.md` и отчёт брифа 1 в `docs/briefs/reports/`.

## Зона
`src/lib/comfy/{client,queue,stage-run}.ts`, `scripts/comfy-queue.ts`, `src/instrumentation.ts`, `src/app/api/comfy/**`, `src/app/api/shots/[shotId]/stages/[stage]/run/route.ts`.

## Задачи

1. **Граф и код склеены через node id.** `stage-run.ts` знает, что в `location_views_multiple_angles.json` картинка — нода `"25"`, текст — `"100","110","120","130"`; в видео — `"129:93"`, `"129:86"`, `"129:161"`; в первом кадре — `"470","902","903","488","477"`. Пересохранил граф — id поменялись, прогон сломан без явной ошибки. Нужен **манифест привязки** рядом с графом (`playbooks/workflows/comfy/<graph>.bind.json`): слоты `images[]`, `text`, `seed[]`, `filename_prefix[]`, `duration`; опциональные ноды, которые удаляются при пустом слоте. `stage-run` становится общим: «граф + манифест + значения → prompt». Если в манифесте указанной ноды нет в графе — понятная ошибка, а не тихий прогон. Формат опиши в `docs/contracts/graph-binding.md`. Манифесты для текущих графов составь по коду и передай модулю 4.
2. **Текст для модели — только `prompt.md`.** После брифа 1 `llm_notes.md` в раннере не читается. Убери оставшиеся эвристики `generationText()`, которые выкидывают строки по регэкспам («Собери », «Локация:», строки с именами). Что остаётся от подстановок (имена → «the person», хвост «Realistic, natural movement») — перенеси в манифест или плейбук модели, чтобы было видно и можно было менять без кода. Согласуй с модулем 4.
3. **Фоновые циклы внутри Next.** Очередь и dispatch стартуют в `instrumentation.ts` с флагами на `globalThis`; при HMR код цикла может остаться старым. Есть ещё `npm run comfy-queue`, который может работать параллельно. Выбери один режим: отдельный процесс воркера (`npm run worker`, Next его не запускает) или только внутри Next. Опиши в `README.md`.
4. **Подробности задания.** Время старта и конца, позиция в очереди ComfyUI (`GET /queue`), читаемый текст `node_errors`, список сохранённых файлов. Эти поля нужны UI для фаз `queued/running/error`.
5. **Перезапись файлов.** `finishJob` сохраняет под именем из ComfyUI. Совпадёт имя — старый результат затрётся. Сделай уникальные имена. Байты не перекодируй, чтобы метаданные PNG с воркфлоу сохранились.
6. Этап `characters` доска не запускает: нет API-графа правки одежды (бриф 4, п. 1). Когда граф и манифест появятся, включи этап в общий механизм.
7. `final_render` гоняет тот же `wan22_*_sketch_turbo`. Дождись от модуля 4 отдельного графа или явного решения.

8. **Несколько воркфлоу на этап.** Пользователь хочет добавлять варианты графов и выбирать их по задаче: например, персонаж по референсу, по текстовому описанию, с позой; видео i2v / FLF (сейчас это захардкоженный `videoWorkflow`). Манифест графа должен описывать: этап, название для меню, обязательные входы (refs, approve предыдущих этапов или только текст), слоты. Доска выбирает граф по полю `workflow` этапа (выбор в UI, по умолчанию — первый подходящий), агент может предложить другой. Добавление нового графа = положить JSON + манифест в `playbooks/workflows/comfy/`, без правки кода. Обобщи `videoWorkflow` (i2v/flf) в этот механизм.

## Результат
- `docs/contracts/comfy-job.md`, `docs/contracts/graph-binding.md`.
- Общий раннер на манифестах. Для location / first_frame / video_preview итоговый prompt JSON совпадает с текущим (сверь до/после на одном кадре без отправки в ComfyUI).
- Тесты: сборка prompt из графа + манифеста; очередь с подменённым `fetch` (ComfyUI недоступен → задание остаётся в `queued`).
