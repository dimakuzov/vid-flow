# Отчёт: бриф 1, единое состояние этапа

Ветка `stage-state`.

## Сделано
- `src/lib/series/stage-state.ts`: `stage_state.json`, фазы `idle | agent | comfy | error`; видимые фазы `agent | queued | running | error` (queued/running берутся из файла задания по `jobId`, чтение без записей). `assertStageFree`.
- `StageStatus`: убран `waiting`, добавлены `agent`, `queued`, `running`, `error`. Активная фаза перекрывает статус из папок (`deriveStageStatus`).
- Отправка агенту: проверка занятости, рекомендация переносится в `agent_request.json`, `llm_notes.md` очищается доской сразу, фаза `agent`.
- Раннер Comfy (`stage-run.ts`) больше не читает `llm_notes.md`: в модель идёт только `prompt.md`. Ручной запуск закрыт, пока этап занят.
- Фоновый цикл (`agent-dispatch.ts → reconcileStage`): agent → comfy / idle / error (таймаут `FRAMEBOARD_AGENT_TIMEOUT_MIN`, по умолчанию 60), comfy → idle / error. Старые запросы без `stage_state.json` обрабатываются как раньше.
- Отмена: `POST /api/shots/{shotId}/stages/{stage}/cancel` (запрос → `cancelled`, задание очереди → `cancelled`, снятие из ComfyUI через `/queue delete` и `/interrupt`, если выполняется именно оно). Очередь перечитывает задание перед отправкой, чтобы не отправить отменённое.
- `markStageReview` удалён: он писал статус в кадр открытого эпизода, даже если задание было из другого.
- UI: клетка подсвечивается и показывает время начала операции, текст ошибки; в меню вместо «Запустить» — «Отменить», для ошибки — «Сбросить ошибку». На странице этапа — полоса состояния, «Отправить агенту» закрыта, поля Prompt и Рекомендация только для чтения, пока этап занят. «Запустить» сначала сохраняет поля.
- Исправлена ошибка типов `series-board.tsx:154`.
- Инструкции: `AGENTS.md`, `docs/AGENT_BOOTSTRAP.md`, `playbooks/stages/characters*.md`, `playbooks/workflows/characters_comfy*.md`, шаблоны в `agent-request.ts` — агент не трогает `llm_notes.md`, `status.json`, `stage_state.json`; сигнал окончания — только `agent_request.json → done`.
- Контракт: `docs/contracts/stage-folder.md`.
- Тесты: `src/lib/series/stage-state.test.ts` (8 сценариев), `npm test`.

## Риски
- Фоновый цикл обходит только открытый эпизод (как и раньше). Если запрос отправлен в эпизоде A, а открыт B, фаза A не сдвинется до возврата в A. Чтение статуса при этом корректно. Исправление — бриф 2.
- `eslint` показывает 11 старых ошибок `react-hooks/refs` в `stage-workspace.tsx` (логика слияния опроса с вводом, строки ~300–360). Код не мой, остаётся для брифа 6.
