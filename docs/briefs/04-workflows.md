## Найденные проблемы

1. **Самый ненадёжный этап — characters.** Для location, first_frame и видео в `workflows/comfy/` лежит готовый граф в API-формате, доска подставляет картинки и текст и сама ставит его в очередь. Для правки одежды (основной путь этапа) такого файла нет: есть только граф позы со скелетом. Поэтому агент каждый раз собирает запрос к ComfyUI с нуля по таблице нод в `workflows/characters_comfy.en.md`, а доска этап не запускает (`stage-run.ts` бросает ошибку). Экспортируй граф правки одежды в API-формат (`character_outfit_qwen21.json`) и опиши слоты. Тогда этап станет как остальные: агент пишет текст, доска запускает. Граф со скелетом оставь отдельным, по явной просьбе.
2. **Нет графа для первого кадра без персонажей и локации** (text-to-image или edit по refs). Нужен граф + описание, иначе правило «собери кадр сразу» невыполнимо.
3. **final_render не определён.** Реши и запиши: какая модель, разрешение, апскейл/интерполяция. Положи граф или явно напиши, что финал пока = превью.
4. **Манифесты привязки.** Модуль 3 вводит `<graph>.bind.json` (формат — `docs/contracts/graph-binding.md`). Ты сопровождаешь их: при любом пересохранении графа манифест обновляется в том же коммите. Добавь проверку-скрипт по согласованию с модулем 3 или опиши ручную проверку в `workflows/comfy/README.md`.
5. **Что такое `prompt.md`.** Сейчас при создании кадра туда пишутся русские инструкции агенту («Собери shot-вариант…, Правила: playbooks/...»), а в модель уходит отфильтрованный регэкспами остаток. Предложи раздельную схему: инструкция этапа живёт в плейбуке, а `prompt.md` — ровно текст для модели, на языке модели. Для каждого графа опиши шаблон этого текста в `models/*.md`. Согласуй с модулями 2 и 3 (кто читает и пишет).
6. **RU + `.en.md`.** `.en.md` читает агент, русские — для пользователя. Правило: меняешь смысл в одной версии — обнови вторую в том же коммите. Сверь существующие пары: где английская версия отстала по смыслу от русской, допиши. Запиши правило в `playbooks/README.md`.
7. **Устаревшее:** `workflows/comfy/README.md` говорит «Frameboard граф не запускает» — уже запускает. Модели в `characters_comfy.md` расходятся с моделями в JSON-графе позы («bf16 UNET name in the JSON is not on this machine»). Приведи графы к установленным моделям или вынеси имена моделей в манифест.
8. **Статусы.** После брифа 1 агент статус этапа не пишет. Проверь, что в плейбуках не осталось указаний ставить `status.json` в `done` или чистить `llm_notes.md`.

9. **Несколько графов на этап** (см. бриф 3, п. 8). Для каждого варианта (персонаж по референсу / по тексту / с позой; видео i2v / FLF) — свой граф, манифест и раздел в `models/*.md`: когда выбирать этот вариант. Агенту нужно правило выбора, пользователю — понятные названия в меню.

## Результат
- Для каждого этапа: граф API + `.bind.json` + `models/<...>.md` с шаблоном текста + `stages/<stage>.md` с критериями приёмки результата (что считать хорошим кадром).
- Обновлённые `playbooks/README.md` и `workflows/comfy/README.md` с таблицей «этап → граф → манифест → кто запускает».
- Список того, что нужно проверить вручную в ComfyUI (ты сам ComfyUI не запускаешь, если пользователь не попросил). Экспорт графа одежды в API-формат делает пользователь в ComfyUI — подготовь ему точную инструкцию, что открыть и что сохранить.
