# Stage: location

Оригинал на русском. Для модели: `playbooks/stages/location.en.md`.

Shot-вариант локации без персонажей. Общий вид берётся из базы серии, ракурс и правки этого кадра собираются здесь.

Промпты: `playbooks/models/qwen_location.md`. Запуск графа ракурсов: `playbooks/workflows/location_comfy.md`.

## Зависимость от базы

```text
data/locations/{locationId}/
  view.png          # общий вид, один исходник на локацию
  description.txt   # предметы, цвета и материалы, которые реально есть на view.png
```

`{locationId}` — имя из `scenario.md` эпизода (`night_cafe`, `street_rain`). Кадр лежит в `data/episodes/{episodeId}/shots/{shotId}/location/`. В один проход берётся один `view.png`. Старые варианты в подпапках базы не подмешивать.

Дополнительные фото предметов (остановка, фонарь) лежат в той же папке и попадают в `refs/` кадра только когда правка их использует.

## Контракт кадра

```text
shots/{shotId}/location/
  refs/  output/  approve/
  prompt.md  llm_notes.md  refs.md  workflow.md  status.json
```

`workflow.md` — необязательная заметка. Можно оставить пустым.

В `approve/` — один выбранный файл. Он идёт в `first_frame`. Имя: `{locationId}_{shotId}.png`.

Отдельной папки `env/` нет. В старых заметках это был `S<номер>/env/env.png`.

## Что класть в refs/

| Файл | Роль |
| --- | --- |
| `{locationId}_view.png` | image 1, наша локация. Копия `view.png` из базы |
| `angle.png` | image 2 только для сложного ракурса: чужая картинка с нужной камерой. Её предметы и свет не копировать |
| фото предмета | image 3, 4… только в проходе правки, когда объект надо поставить как на фото |

## Какой проход

| Задача | Проход |
| --- | --- |
| Простой поворот, другая крупность, камера чуть выше или ниже | A. Граф `playbooks/workflows/comfy/location_views_multiple_angles.json` |
| Разворот около 180° или большая смена высоты | Сначала промежуточный вид на уровне глаз, потом ещё один шаг A. Если не держится — сложный ракурс через Qwen Image 2.1, два референса |
| Убрать или добавить объект, сменить свет или сезон, почистить картинку | B. Отдельный edit-проход Qwen Image 2.1. Своего графа в репозитории нет |

Свет на проходе A не менять. Малую глубину резкости модель почти не рисует: фон оставлять резким.

Чаще всего в работу идёт ветка **objects** (кадр через предметы с референса). Ветка **camera** — для простого поворота. Ветка **simple** — только для близкого ракурса.

## Порядок

1. Взять `view.png` и `description.txt` из базы.
2. Выбрать проход по таблице.
3. Для A запустить четыре ветки и сложить результаты в `output/`: `{shotId}_v1_simple.png`, `{shotId}_v2_objects.png`, `{shotId}_v3_camera.png`, `{shotId}_v4_camera_objects.png`.
4. Выбрать лучший. Если ракурс не вышел за один запуск A, не крутить его бесконечно: промежуточный вид или сложный ракурс.
5. Свет, объекты и чистку делать следующим проходом B, а не переписывать весь промпт.
6. Выбранный файл положить в `approve/{locationId}_{shotId}.png`.

В кадре нет людей. Если люди есть на базе, сначала убрать их отдельной правкой.
