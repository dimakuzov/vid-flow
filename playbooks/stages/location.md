# Stage: location

Оригинал на русском. Для модели: `playbooks/stages/location.en.md`.

Shot-вариант локации без персонажей. Общий вид берётся из базы серии, ракурс и правки этого кадра собираются здесь.

Промпты: `playbooks/models/qwen_location.md`. Запуск графа ракурсов: `playbooks/workflows/location_comfy.md`. Новая локация с нуля: `playbooks/models/krea2_location.md`.

## Зависимость от базы

```text
data/locations/{locationId}/
  view.png          # общий вид, один исходник на локацию
  description.txt   # предметы, цвета и материалы, которые реально есть на view.png
```

`{locationId}` — имя из `scenario.md` эпизода (`night_cafe`, `street_rain`). Кадр лежит в `data/episodes/{episodeId}/shots/{shotId}/location/`. В один проход берётся один `view.png`. Старые варианты в подпапках базы не подмешивать.

Дополнительные фото предметов (остановка, фонарь) лежат в той же папке и попадают в `refs/` кадра только когда правка их использует.

## Контракт кадра

```text
shots/{shotId}/location/
  refs/  output/  approve/
  prompt.md  llm_notes.md  refs.md  workflow.md  status.json
```

`workflow.md` — необязательная заметка. Можно оставить пустым.

В `approve/` — один выбранный файл. Он идёт в `first_frame`. Имя: `{locationId}_{shotId}.png`.

Отдельной папки `env/` нет. В старых заметках это был `S<номер>/env/env.png`.

## Что класть в refs/

| Файл | Роль |
| --- | --- |
| `{locationId}_view.png` | image 1, наша локация. Копия `view.png` из базы |
| `angle.png` | image 2 только для сложного ракурса: чужая картинка с нужной камерой. Её предметы и свет не копировать |
| фото предмета | image 3, 4… только в проходе правки, когда объект надо поставить как на фото |

## Какой граф

В меню «Воркфлоу» этапа три варианта:

| Вариант | Когда |
| --- | --- |
| `location_views` — «Локация: 4 ракурса по общему виду» (Qwen, order 10) | Локация есть в `data/locations/` или её общий вид лежит в `refs/`. Нужна та же комната с другой точки. Комнату сохраняет |
| `location_krea2` — «Локация с нуля: Krea 2 по тексту» (order 20) | Локации нет в библиотеке. Или нужен свежий вариант пространства — например, будущий `view.png` для новой папки библиотеки. Картинка из `refs/` — только смысловой референс: комнату Krea 2 рисует заново |
| `location_firered` — «Локация из референсов: FireRed» (order 30) | Новая локация собирается из 1–3 картинок, которые пользователь положил в `refs/`. Промпт: `playbooks/models/firered_location.md`. Больше трёх референсов запуск не берёт |

По умолчанию доска берёт первый доступный: при общем виде — `location_views`, без него — `location_krea2` (картинка ему не обязательна). Нужна Krea 2 при наличии общего вида — выбрать её в меню. Агент, если считает, что лучше Krea 2, предлагает её полем `suggestedWorkflow: "location_krea2"`.

Правка готовой Krea-картинки (свет, предмет, чистка) — проход B ниже, другой ракурс той же Krea-комнаты — проход A с ней в `refs/`.

## Локация из библиотеки

Модель, размечая сценарий, могла не узнать локацию. Кнопка «Из библиотеки» у «Референсы» (только на этом этапе) показывает папки `data/locations/` с миниатюрой и кладёт общий вид в `refs/` как `{locationId}_view.png`. Существующий файл не затирается. Граф берёт первый файл `refs/`, поэтому выбранная локация сразу становится входом. Галка «Записать в кадр» ещё и меняет `- location:` в `shot.md`. Агент `refs/` после такого выбора не пересобирает (`agent_touch.json`).

## Локация — фон первого кадра

Утверждённая локация становится image 1 первого кадра и остаётся там фоном без изменений. Промпт первого кадра камеру не двигает. Поэтому локацию снимают так, как нужно кадру. План берётся из первых слов текста кадра (`Close up`, `Medium shot`, `Long shot`); сообщение пользователя важнее.

| План | Что показывает локация |
| --- | --- |
| Общий | Всё пространство, где идёт действие, на уровне глаз. Место для людей свободно и видно |
| Средний | Вид примерно с двух метров от места, где будут люди: то, что за ними (окно, парта, доска), такого размера, каким оно будет за человеком по пояс. Нижняя часть кадра — место для людей. В ep2 средний план профессора вышел сразу: локация уже была снята с расстояния кафедры. Девушки у окна (s07) шли дольше: локация — окно в полный рост, и модель всё время его перерисовывала |
| Крупный | Хватает фрагмента за головой: часть стены, окна, несколько парт, близко. В ep2 крупный план на гладкой деревянной панели приняли с первого прогона, а крупные планы на общем виде зала выходили общими |

Место для людей писать в промпт: `the empty chair in the center of the frame where she will sit`, `the window on the right half of the frame, the floor in front of it free`. Предметы — только важные для действия: по ним первый кадр привязывает масштаб.

Кадры в одной локации держат одну комнату: брать другой ракурс утверждённого вида (проход A), а не рисовать новую комнату на каждый кадр.

## Какой проход

| Задача | Проход |
| --- | --- |
| Простой поворот, другая крупность, камера чуть выше или ниже | A. Граф `playbooks/workflows/comfy/location_views_multiple_angles.json` |
| Разворот около 180° или большая смена высоты | Сначала промежуточный вид на уровне глаз, потом ещё один шаг A. Если не держится — сложный ракурс через Qwen Image 2.1, два референса |
| Убрать или добавить объект, сменить свет или сезон, почистить картинку | B. Отдельный edit-проход Qwen Image 2.1. Своего графа в репозитории нет |

Свет на проходе A не менять. Малую глубину резкости модель почти не рисует: фон оставлять резким.

Чаще всего в работу идёт ветка **objects** (кадр через предметы с референса). Ветка **camera** — для простого поворота. Ветка **simple** — только для близкого ракурса.

## Порядок

1. Взять `view.png` и `description.txt` из базы.
2. Выбрать проход по таблице.
3. Для A запустить четыре ветки и сложить результаты в `output/`: `{shotId}_v1_simple.png`, `{shotId}_v2_objects.png`, `{shotId}_v3_camera.png`, `{shotId}_v4_camera_objects.png`.
4. Выбрать лучший. Если ракурс не вышел за один запуск A, не крутить его бесконечно: промежуточный вид или сложный ракурс.
5. Свет, объекты и чистку делать следующим проходом B, а не переписывать весь промпт.
6. Выбранный файл положить в `approve/{locationId}_{shotId}.png`.

В кадре нет людей. Если люди есть на базе, сначала убрать их отдельной правкой.
